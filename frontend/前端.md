
# CodeWiz Frontend 架构分析

## 一、技术栈

| 层 | 技术 |
|---|------|
| 框架 | **Next.js 16** (App Router) + React 19 |

| AI 对话 | **Vercel AI SDK v6** (`ai` + `@ai-sdk/react` + `@ai-sdk/openai`) |

| Markdown | `remark-gfm` + `@assistant-ui/react-markdown` |

## 二、路由结构 (App Router)

```
app/
├── page.tsx                          # "/" → 首页 (Assistant + HomeWelcome)
├── layout.tsx                        # 根布局 (AuthProvider > WorkspaceFrame)
├── assistant.tsx                     # 核心 AI 对话组件 (useChat + assistant-ui)
├── workspace-frame.tsx               # 监听路由/事件，传递 repoId/conversationId
├── home-workspace.tsx                # 首页 workspace shell 组装
│
├── [repoId]/
│   ├── page.tsx                      # "/:repoId" → 项目页 (无选中对话)
│   ├── repo-workspace-shell.tsx      # 项目 Shell (侧栏 + 预览 + 对话区)
│   └── [conversationId]/
│       └── page.tsx                  # "/:repoId/:conversationId" → 对话页 (加载历史)
│
├── api/
│   ├── chat/route.ts                 # POST → 代理到 AI Service /api/chat (SSE)
│   ├── repos/route.ts                # GET/POST → 代理到 Go Backend /api/projects
│   ├── repos/[repoId]/
│   │   ├── conversations/route.ts     # GET/POST → 对话列表/创建
│   │   └── conversations/[conversationId]/route.ts  # GET → 对话详情
│   ├── sandbox-preview/[repoId]/[[...path]]/route.ts  # GET → 代理沙箱静态文件
│   ├── sandbox-status/[repoId]/route.ts  # GET → 沙箱状态
│   ├── sandbox-terminal/[repoId]/route.ts  # GET → 代理沙箱终端 (ttyd)
│   └── _lib/
│       ├── go-api.ts                 # Go 响应解包工具
│       └── upstream-auth.ts          # 上游鉴权 Token 传递
│
└── auth/
    ├── login/page.tsx                # 登录页
    └── register/page.tsx             # 注册页
```

**路由关键点：**

1. **三层路由体系**：`/` (首页) → `/:repoId` (项目) → `/:repoId/:conversationId` (对话)
2. **Next.js Route Handler 作为 BFF**：所有 `/api/*` 路由都是代理层，把浏览器请求转发到 Go Backend 或 AI Service
3. **sandbox-preview 代理**：iframe 加载沙箱内容时走同源代理，避免跨域和 HTTPS 拦截
4. **sandbox-terminal 代理**：iframe 加载 ttyd 终端时走同源代理，与预览 URL 完全分离

## 三、核心组件职责

### 1. `assistant.tsx` — AI 对话心脏

职责：封装 Vercel AI SDK useChat + assistant-ui RuntimeProvider

| 功能 | 实现 |
|------|------|
| 对话流 | `useChat()` 连接 `/api/chat` → AI Service (SSE) |
| 运行时 | `useAISDKRuntime()` 桥接 AI SDK ↔ assistant-ui |
| 路由切换 | 监听 `codewiz:go-home` / `codewiz:go-to-repo` 自定义事件 |
| 项目创建 | 监听 `codewiz:create-from-github` 事件，调用 Go API 创建项目 |
| 历史加载 | `initialMessages` 传入时加载历史消息 |
| 回调 | `onActiveConversationChange` 通知外层路由变更 |

### 2. `workspace-frame.tsx` — 路由导航协调器

- 从 URL pathname 解析 `repoId` / `conversationId`
- 监听自定义事件 (`codewiz:active-conversation`, `codewiz:go-home`, `codewiz:go-to-repo`)
- 将 `effectiveRepoId` + `effectiveConversationId` 下传到 `RepoWorkspaceShell`

### 3. `repo-workspace-shell.tsx` — 项目工作区 Shell

**最重的组件** — 承担了过多职责：

| 职责 | 现状 |
|------|------|
| 项目列表加载 | `loadRepos()` 调用 `/api/repos` |
| 轮询刷新 | 当 `threadIsRunning` / `hasDeployingRepo` 时每 10s 刷新 |
| 沙箱管理 | `sandboxOverrides` 状态管理 |
| 预览 iframe | 管理左右分栏 (代码/预览) |
| Terminal | iframe 内嵌终端管理 |
| Context 注入 | `ReposContextInner` + `ProjectConversationsContextInner` |
| Publish dialog | 发布弹窗 |


**关键数据流：**

1. **对话流**：`assistant.tsx` → `useChat({api: "/api/chat"})` → Next.js Route Handler → AI Service SSE
2. **项目流**：组件直接 `fetch("/api/repos")` → Next.js Route Handler → Go Backend
3. **鉴权流**：Token 存在 `localStorage` → `clientAuthHeaders()` 注入 → 或通过 cookie `codewiz_token` 服务端读取
4. **沙箱预览流**：iframe `src=/api/sandbox-preview/:repoId` → Next.js 反向代理 → AI Service 沙箱静态文件端口
5. **沙箱终端流**：iframe `src=/api/sandbox-terminal/:repoId` → Next.js 反向代理 → AI Service ttyd WebSocket 端口

## 五、鉴权机制

```
Browser:
  localStorage: codewiz_token          ← JWT token
  cookie:       codewiz_token          ← 服务端 API Route 读取

API Route (server-side):
  优先级: req.headers.authorization > cookie > URL query (?auth_token=)

客户端请求:
  clientAuthHeaders() → 从 localStorage 注入 Authorization header

iframe 场景:
  appendAuthParam(url) → 把 token 注入 URL query
```

**问题**：双重存储 (localStorage + cookie) 增加了一致性风险，但都指向同一个 JWT，服务端只验证 JWT 有效性。

## 六、Context 体系 (状态管理)

```
AuthProvider (auth-context.tsx)
  └── { user, isLoading, isAuthenticated, logout, refreshUser }

ReposContext (repos-context.tsx)          ← 由 RepoWorkspaceShell 注入
  └── { repos[], isLoading, error, refresh, onSelectProject }

ProjectConversationsContext (project-conversations-context.tsx)  ← 由 RepoWorkspaceShell 注入
  └── { repoId, conversations[], isLoading, refresh, onSelectConversation }
```

**问题**：`zustand` 由 `@assistant-ui/react` 内部使用 (`useShallow`)。Context 嵌套层级较深：
`AuthProvider > WorkspaceFrame > RepoWorkspaceShell > ReposContextInner + ProjectConversationsContextInner > children`

## 十、扩展建议

1. **接入 AI Service 的多模型切换**：前端只需在 `assistant.tsx` 的 `useChat` 中传递 `body: { provider: "deepseek", model: "..." }`，配合已重构的 `get_llm()` 工厂即可
2. **System Prompt 动态化**：改为从 `/api/system-prompt?repoId=xxx` 动态获取，包含实际沙箱目录结构
3. **Context 层级简化**：考虑将 `ReposContext` 和 `ProjectConversationsContext` 提升或合并，减少嵌套深度
